# Directory guide

The repository separates application source, resources shipped in the executable, original media, and platform deployment tools.

```text
.
├── Cargo.toml / Cargo.lock     Rust package and dependency lockfile
├── build.rs                    CXX-Qt, QML, resources, and Windows resource build
├── src/
│   ├── main.rs                 Application entry point
│   ├── backend.rs              Qt bridge, networking, and application state
│   ├── domain.rs               Flight archive and schedule logic
│   └── cpp/                    Qt helpers and JPEG XL image provider
├── qml/                        The org.starship.journal QML module
├── resources/
│   ├── resources.qrc           Qt resource manifest with stable runtime aliases
│   ├── data/                   Flights, schedule snapshot, and photo credits
│   ├── fonts/                  Bundled fonts and provenance
│   ├── themes/                 Application color scheme
│   ├── photos/                 Prepared flight photography
│   ├── images/                 SpaceX photographs for Flights 4 and 7
│   └── icon.svg                Application icon
├── assets/archive/
│   ├── originals/              Original JPEG downloads
│   ├── jxl/                    Lossless archival JPEG XL copies
│   ├── metadata/               Gallery download metadata
│   ├── spacex-reference/       Reference photography
│   └── *.json                  Gallery selection and conversion records
├── packaging/
│   ├── linux/                  Desktop launcher
│   ├── windows/                Icon, manifest, resource file, SDK list, QML imports
│   └── macos/                  Icon renderer
├── scripts/
│   ├── build/                  Build and package each platform
│   ├── package/                Collect dependencies and create distributables
│   ├── prepare/                Prepare photography and cache KDE Breeze
│   ├── check/                  Native and extracted-package smoke checks
│   └── release/                Publish CI prereleases
├── tests/packaging/            Python packaging unit tests
├── docs/
│   ├── building.md             Platform builds and prereleases
│   ├── content-sources.md      Flight research and precision notes
│   └── previews/               Curated screenshots and motion preview
├── .github/workflows/builds.yml
├── target/                     Ignored build output, SDKs, runtime cache, diagnostics
└── dist/                       Ignored distributable packages, created by packaging
```

## Editing the application

Change Rust behavior in `src/` and the interface in `qml/`. Register new QML files in `build.rs`; the flat QML directory keeps all components in the same module. Rust unit tests remain in their corresponding modules.

Edit flight content in `resources/data/flights.json` and record research in [content-sources.md](content-sources.md). Update the bundled schedule in `resources/data/schedule.json`. The Rust domain module embeds both JSON files at compile time.

Add bundled fonts or photographs to `resources/` and register them in `resources/resources.qrc`. Its aliases define the resource URLs used by the interface, independently of filesystem paths. Photo preparation reads selections from `assets/archive/selection.json`, keeps full-resolution originals and archival encodings under `assets/archive/`, and writes resized application images under `resources/`.

`target/runtime/` holds the optional locally cached Breeze runtime. It is generated by `scripts/prepare/prepare-native-style.py` and discovered by the C++ Qt helpers. Build output and downloaded SDKs also remain under `target/`; curated previews belong in `docs/previews/`.

## Common commands

Run these commands from the repository root:

```sh
cargo run --release
bash scripts/check/check-native.sh
python -m unittest discover -s tests/packaging -v
python scripts/prepare/prepare-photos.py
python scripts/prepare/prepare-native-style.py
```

Platform build scripts change to the repository root before running:

```sh
bash scripts/build/build-linux.sh
bash scripts/build/build-windows.sh
bash scripts/build/build-macos.sh
```

These scripts run backend tests and compile the application before invoking the corresponding script in `scripts/package/`. Platform prerequisites and release behavior are described in [building.md](building.md) and the [README](../README.md).

The Windows package check is `scripts/check/check-windows.ps1`; Linux and macOS packagers call `scripts/check/check-portable.py`. CI uses `.github/workflows/builds.yml` and publishes through `scripts/release/publish-prerelease.sh` after all platform checks succeed.
